# FIREFLY ABSA v2 使用说明

本版将“这条内容与萤火虫是否有关”“它是否包含产品反馈”和“具体评价哪个功能”分开处理。所有导入来源仍可在原文库查看；观点分析只纳入相应的有效产品表达。旧结果不会因升级自动改写，也不会因启动工具或导入文件自动发起模型请求。

## 日常流程

1. 导入笔记和评论。稳定来源标识用于去重；正文改变仍沿用原来源，保留历史。
2. 在设置中填写服务地址、模型、密钥、输入/输出价格和月预算。价格使用你的服务商实际计价，工具不会猜测。默认并发数为 2，可设置 1–4；输出 token 上限仍由你控制。
3. 选择待分析、失败项、选中来源或旧版结果，先预估。预览显示当前原文和品牌语境；费用预估含允许的额外修复请求。更改来源或设置后需重新预估。
4. 明确开始后才执行请求。纯表情、标点或链接可在本地跳过并保存过滤原因；“死机”“没声音”“不跟车”等短故障文本不会按长度丢弃。
5. 查看成功、失败、跳过数量及待复核原因。可以筛选一级模块、二级功能、内容类型、范围、分析版本和待复核状态，再打开原文校对或修正观点。
6. 从当前筛选导出 CSV，保留标准类别、原文对象、评价表达、证据、隐含标记和版本信息，便于追溯。

同一次分析对单条来源完成内容分流和观点抽取，再由本地规则检查字段、标签和原文跨度。技术校验通过只表示格式与约束通过，不代表人工认定的语义准确。

## 内容分流

| 字段 | 取值 | 用途 |
| --- | --- | --- |
| 品牌相关性 `brand_relevance` | `related` / `unrelated` / `uncertain` | 评价是否属于 FIREFLY；不能把竞品评价移植到萤火虫 |
| 产品范围 `product_scope` | `cockpit` / `other` / `mixed` / `unknown` / `not_applicable` | 区分座舱、其他车辆/服务问题及混合范围 |
| 内容类型 `content_types` | `product_feedback` / `product_question` / `promotion` / `delivery_chat` / `chitchat` / `other` / `uncertain` | 可多选，推广与真实体验混合时保留两类 |
| 复核原因 `review_reasons` | 简短原因列表 | 解释品牌、类别、情感等不确定项 |

品牌相关不等于存在可用观点。纯推广、报交付日期、打招呼、附和等不能被强行抽取为功能评价。混合内容中真实的产品反馈或具体功能咨询仍可保留。无关内容不得带有 FIREFLY 观点。

销售服务、价格、交付、充电续航、轮胎底盘和其他车辆功能有各自类别，不强塞进座舱模块。来源分流不会删除原文；过滤原因可查看，误过滤可人工修正恢复。

## 观点字段与二级功能

优先研究四个一级模块：智能硬件、辅助驾驶、语音助手（lumo）、车机。每个观点必须选定正式词表中的一个二级功能；模块和二级功能的组合由本地校验。

| 一级模块 | 二级功能示例 |
| --- | --- |
| 智能硬件 | 中控屏／仪表屏、麦克风、扬声器／音响、摄像头、USB／无线充电 |
| 辅助驾驶 | ACC、车道保持、跟车、泊车、感知、安全感与接管体验 |
| 语音助手（lumo） | 唤醒、语音识别、语义理解、多轮对话、指令执行、响应速度 |
| 车机 | 导航、导航-路线规划、导航-定位、网络、系统流畅度、系统稳定性、蓝牙与手机互联、OTA |

完整词表以应用选项与 `absa.py` 的 `TAXONOMY` 为准。标准类别由一级模块与二级功能组成，用于聚合；原文对象和评价表达保留用户自己的用词。

- `target_text`：用户明确提到的评价对象；隐含对象填 `null`，同时 `implicit_target=true`。
- `opinion_text`：用户明确表达的评价；隐含评价填 `null`，同时 `implicit_opinion=true`，并标记需要复核。
- `evidence`：当前来源中的连续原文，须包含显式目标与评价。不能删字、拼接、改写或从母笔记借来。
- `feedback_type`：`fault`（故障）、`complaint`（抱怨）、`suggestion`（建议）、`question`（咨询）、`praise`（夸奖）、`comparison`（对比）、`other`。
- `sentiment`：`positive` / `negative` / `neutral` / `uncertain`。涉及多个观点或正负对比时拆成多条，不使用 `mixed` 情感。
- `needs_review`：类别或情感不确定、隐含评价等情况需要人工复核。
- `context_used`：本期必须为 `false`。

例如“车机卡”的合成标注可以是车机 / 系统流畅度，对象“车机”、评价“卡”、证据“车机卡”；“死机”的对象可为隐含，不补写一个原文里不存在的对象词。模型不能凭常识猜测故障根因。

分类时区分“语音听错”和“听对但不理解”，“听懂但不执行”和“响应慢”；区分音响本体问题与音乐应用卡顿；更新后系统崩溃归系统稳定性，不能仅因出现“更新后”就新增 OTA 故障。

## 本期语境边界

母笔记仅用于确认品牌归属，不提供当前评论的对象、评价或证据。模型输入不包含父评论，不执行父子评论关系推理。仅有“我也是”的附和不会继承父评论的故障类别或凭空补出观点，而会保留原文并说明复核原因。

因此 `context_used=true` 会被当前版本拒绝。相应能力留待有独立标注与验证的后续版本；不能将“系统保留了关联评论供人阅读”误当成“模型已经利用父评论推理”。

## 请求、并发与费用

请求使用共享 HTTP 连接；任务默认同时处理 2 条来源，最多配置为 4 条。相同输入的并发请求受同步保护以避免重复扣费，已验证的缓存可以复用。这里描述的是实现方式，不是经过实测的速度提升承诺。

每次真实请求（包括格式修复）都必须单独预留预算，返回可核算用量后结算。预估覆盖首个请求及允许的额外尝试；月预算检查与预留在同一事务中完成，不能因并发分别读到余额而越过预留约束。未知用量保留预估金额，预算只涵盖本工具的请求，不能代表服务商账户全部消费。停止操作会阻止继续派发，已在途的请求仍可能完成或计费。

`format_retries` 默认为 1，可设为 0；单个来源最多是首个请求加一次额外尝试：

- 返回 JSON / 字段 / 证据校验失败，且服务商已提供可核算用量时，可发送一次固定的格式修复说明。修复再次预留预算，不无限循环。
- 明确连接失败可按零用量结算，并在允许的额外尝试次数内重试。
- 超时、传输中断、未明确可核算的 HTTP 异常和未知账单状态，不会自动追加可能付费的重试。
- `finish_reason=length` 明确标为截断；即使截断内容恰好可解析为 JSON，也不会当作正常完成。需检查输出上限等配置，重新预估后手动重试，不自动放大 token 上限。

针对 `open.bigmodel.cn` 的 GLM 5.2 / 5.3 型号系列，适配层按设置发送 `reasoning_effort`，默认 `low`；其他主机和型号不发送该专属参数。参数兼容限制依据适配器配置，不表示其他厂商 API 也支持此字段。

## 旧数据与人工保护

数据库采用新增字段兼容原有记录；历史观点保留旧标签并显示旧版标记，不给旧记录编造原文对象、二级功能或隐含标记。重新分析前，上次有效结果仍然保留；失败不能用不完整输出覆盖原结果。

“旧版结果”范围只挑选符合条件的旧 AI 来源，不自动处理人工修改的结果或账单状态未知的请求。先预估，再明确开始；重分析成功才写入新结构。人工保存的结果受保护，正在运行的任务也会重新检查来源版本和人工修改标志。

人工编辑时可以修正内容分流和观点，但仍需满足原文跨度与模块对应规则。混合保留的旧观点不会因为更新分流字段就被伪装为完整 v2 观点；需要逐项核验后才能视为新版标注。

## 如何看技术指标与模型质量

费用页/分析信息可展示请求成功率、JSON 成功率、字段校验成功率、截断率、额外尝试比例、平均和 P95 请求时延及费用。新诊断只保存经过筛选的状态、结束原因、耗时、token 数、模型和规则版本，不保存密钥、原始模型回答或推理文本。历史账本缺少相关诊断时单独计数；没有观测数据的比例返回空值，不能用 0 或 100% 填充。

请求成功不等于 JSON 成功，JSON 成功不等于语义抽取正确，字段校验成功也不等于产品团队认为可直接使用。当前没有基于人工确认金标得出的准确率或可用率结论。

本地已准备 80 条人工标注草稿，全部未确认。真正评估需先人工标注并按笔记隔离开发集与留出集，然后提供相同稳定 ID 的预测，使用离线评估器计算四元组、字段、多标签和路由指标。缺失/失败预测不能从召回分母消失；产品可用率须来自明确的人工判断。标注规则与执行方式见 [ABSA 离线评估说明](absa-evaluation.md)。

## 本地验证

供应商测试全部通过 `httpx.MockTransport` 拦截 HTTP，使用合成密钥和文本，不接触真实模型：

```bash
.venv/bin/python -m pytest tests/test_provider.py tests/test_evaluation.py -q
```

测试覆盖 JSON 诊断、输出截断标记、供应商专属参数边界、HTTP 与网络异常的计费判断、畸形响应、诊断信息不回显私密内容，以及离线指标和标注文件保护。生产模型质量和真实请求性能仍需在用户明确发起的后续评估中观测。
